## CRITICAL LESSONS LEARNED (READ FIRST!)

### 1. NEVER Add `key=` Parameter to `components.html()`
**Crashed production twice!** Streamlit 1.51.0 does NOT support `key=` parameter on `components.html()`.

```python
# WRONG - CRASHES:
components.html(html_code, height=0, key="something")

# CORRECT:
components.html(html_code, height=0)
```

### 2. NEVER Create Streamlit Components Inside Button Handlers
`st_javascript()`, `components.html()`, `LocalStorage()` all create iframe components.
When called inside a button handler BEFORE `st.rerun()`, they cause duplicate component ID errors.

**Pattern that BREAKS:**
```python
if st.button("Save"):
    st_javascript("localStorage.setItem(...)")  # Creates component
    st.rerun()  # Crashes on next render - duplicate ID!
```

**Pattern that WORKS:**
```python
if st.button("Save"):
    st.session_state['_pending_save'] = data
    st.rerun()

# At TOP of page (during normal render):
if st.session_state.get('_pending_save'):
    st_javascript("localStorage.setItem(...)")  # Safe here!
    st.session_state.pop('_pending_save')
```

### 3. `st.markdown("<script>...</script>")` Does NOT Execute JavaScript
Even with `unsafe_allow_html=True`, Streamlit blocks script execution for security.
Use `components.html()` or `st_javascript()` instead.

### 4. `st_javascript()` Returns `0` on First Call
Before JavaScript executes, `st_javascript()` returns integer `0`.
Streamlit auto-reruns once JS executes and returns actual value.

```python
value = st_javascript("localStorage.getItem('key')")
if value == 0:
    # JS hasn't executed yet - wait for rerun
    pass
elif value is None:
    # JS executed, key doesn't exist
    pass
else:
    # JS executed, got actual value
    pass
```
